# C#이란?

C#은 정적 타입 검사를 바탕으로, 객체 지향을 비롯한 다양한 방식으로 프로그램을 작성할 수 있게 만든 범용 고급 언어이다. .Net의 실행 환경과 라이브러리를 활용해 안전성과 개발 생산성을 높이도록 설계되었다.

# 객체지향이란?

객체지향이란 객체마다 상태와 동작에 관한 책임을 부여하고, 객체 간의 상호작용으로 프로그램의 기능을 수행하도록 구성하는 것으로 프로그래밍 패러다임의 관점 중 하나이다.

그렇다면 객체는 무엇일까?

### 객체란?

프로그램에서 하나의 대상으로 구분되며, 상태와 동작을 통해 맡은 책임을 수행하는 단위이다.

## 객체지향이 생겨난 배경

옛날에는 하드웨어와 소프트웨어의 개발 속도차이가 크지 않았다. 그러나 소프트웨어 언어의 발달과 컴파일러의 발달로 하드웨어가 소프트웨어의 발달을 따라오지 못하는 상황이 발생했고, 이는 객체지향 언어가 등장하게 되는 계기로 작용했다.

객체지향 프로그래밍은 개발하려는 것을 기능별로 묶어 모듈화를 함으로써 하드웨어가 같은 기능을 중복으로 연산하지 않도록 하고, 모듈을 재활용하기 때문에 하드웨어의 처리양을 획기적으로 줄여주었다.

## 객체지향의 특성

객체지향의 특성이 왜 생겨났는지를 생각해보면 특성을 이해하기가 쉬울거 같아서 알아봤다.

> "객체가 책임을 맡고, 다른 객체와 협렵하도록 프로그램을 구성하려면 무엇이 필요한가?"

결국에는 객체지향의 의미와 연관되어서 그 의미를 지키기 위해 생겨난 특성들인 것이다.

### 캡슐화

객체를 캡슐로 싸서 그 내부를 보호하고 볼 수 없게 하는 것으로, 객체의 가장 본질적인 특징이다.

외부에서 내부의 직접적인 접근을 제한하는 정보 은닉 기법이다.

### 상속

상위 객체의 속성이 하위 객체에 물려져서, 하위 객체가 상위 객체의 속성을 모두 가지는 관계이다.

기존 코드를 재사용하고 중복을 줄여 개발 효율성을 높여준다.

### 다형성

다형성이란 여러 객체나 특정 함수가 동일한 요청에 따른 기능을 다양한 방식으로 구현할 수 있는 것을 의미한다.

동일한 인터페이스나 클래스를 상속받은 서로 다른 객체가 각자 함수를 다르게 구현할 수 있고(오버라이딩), 같은 함수명을 가지고 다른 타입의 매개변수를 받아 여러 구현을 가질 수도 있다.(오버로딩)

### 추상화

추상화란 객체의 공통적인 속성과 기능을 추출하여 정의하는 것을 의미한다.

불필요한 세부사항을 감추고 공통의 인터페이스나 클래스로 코드의 가독성과 유지보수성을 높여준다. 또한 객체간 의존성을 낮춰준다.

## 객체지향의 장단점

컴퓨터 프로그램을 설계하는데 있어서 객체지향의 관점은 어떤 장단점이 있을까?

### 장점

- 코드의 재활용성이 높다.
- 코드의 변경을 최소화하고 유지보수 하는 데 유리하다.
- 디버깅이 쉽다.

### 단점

- 처리속도가 절차지향보다 느리다.
- 설계에 많은 시간소요가 들어간다.

# 질문 거리

### 프로그래밍 패러다임이란?

개발자가 컴퓨터 프로그램을 설계하고 구현할 때 문제를 바라보는 관점, 방식, 그리고 사고의 틀을 의미한다.

프로그래밍 패러다임은 크게 **명령형**과 **선언형**으로 나뉜다.

명령형 프로그래밍에는 절차적 프로그래밍과 객체지향 프로그래밍이 속한다.

선언형 프로그래밍에는 함수형 프로그래밍과 논리형 프로그래밍이 속한다.
