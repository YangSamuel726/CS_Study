# 명령어 병렬 처리 기법
클럭 속도 높이기, 멀티코어, 멀티스레드 등 하드웨어적으로 CPU의 성능을 높이는 방법도 중요하지만 그만큼 CPU가 놀지 않고 효율적으로 작업하게 하는 것도 CPU 성능에 영향을 미친다. 이에 CPU가 효율적으로 작업하도록 만드는 기법들을 살펴보고자 한다.

# 명령어 파이프라인
명령어 처리 과정을 클럭 단위로 나누어 보면 일반적으로 다음과 같이 나눌 수 있다.

 1. 명령어 인출
 2. 명령어 해석
 3. 명령어 실행
 4. 결과 저장

여기서 중요한 점은 각 단계가 코어의 다른 회로에서 실행되기에 같은 단계가 겹치지 않는다면 CPU는 각 단계를 동시에 실행할 수 있다는 점이다.

마치 공장 생산 라인과 같이 명령어들을 **명령어 파이프라인**에 넣고 동시에 처리하는 기법을 **명령어 파이프라이닝**이라고 한다.

하지만 이 방법에는 위험도 존재한다. 바로 **파이프라인 위험**이다. 크게 **데이터 위험, 제어 위험, 구조적 위험**이 있다.

### 데이터 위험
**데이터 위험**은 명령어 간 '데이터 의존성'에 의해 발생한다. **데이터 의존성**이란 어떤 명령어가 다른 명령어가 만든 데이터에 의존하는 관계를 의미한다. 다시 말해 데이터 의존성이 지켜지지 않아 발생하는 위험을 데이터 위험이라 한다.

어떤 명령어는 이전 명령어를 끝까지 실행해야만 비로소 실행할 수 있는 경우가 있다.

예를 들어 명령어 A의 결과값이 R1(레지스터)에 저장된다고 하자. 명령어 B가 R1의 값을 읽고 R4와 더해 R5에 저장되어야 한다면 명령어 A가 끝나기 전에 B가 실행될 경우 결과값이 저장되기 전의 R1의 값을 읽어들이므로 의도치 않은 동작을 하게 된다. 이러한 위험을 데이터 위험이라 한다.

### 제어 위험
**제어 위험**은 주로 분기 등으로 인한 '프로그램 카운터의 갑작스러운 변화'에 의해 발생한다. 다시 말해 다음에 실행할 명령어의 위치가 확실하지 않아 발생하는 위험이다.

예를 들어 기본적으로 프로그램 카운터는 현재 실행 중인 명령어의 다음 주소로 갱신된다. 하지만 프로그래 실행 흐름이 바뀌어 명령어가 실행되면서 프로그램 카운터 값에 갑작스러운 변화가 생긴다면 명령어 파이프라인에 미리 가지고 와서 처리 중이었던 명령어들은 아무 쓸모가 없어진다. 이를 제어 위험이라고 한다.

참고로 이를 위해 사용하는 기술 중 하나가 **분기 예측**이다. 분기 예측은 프로그램이 어디로 분기할지 미리 예측한 후 그 주소를 인출하는 기술이다.

### 구조적 위험
**구조적 위험**은 명령어들을 겹쳐 실행하는 과정에서 서로 다른 명령어가 동시에 같은 CPU 부품을 사용하려고 할 때 발생한다. 구조적 위험은 **자원 위험**이라고도 부른다. 다시 말해 서로 다른 명령어들이 같은 하드웨어 자원을 동시에 사용하기 위해 발생하는 위험을 구조적 위험이라고 한다.


# 슈퍼 스칼라
**슈퍼 스칼라**는 CPU 내부에 여러 개의 명령어 파이프라인을 포함한 구조이다.

슈퍼 스칼라 구조로 명령어 처리가 가능한 CPU를 **슈퍼스칼라 프로세서, 슈퍼스칼라 CPU**라고 한다.

슈퍼스칼라는 여러개의 파이프라인을 사용하기에 파이프라인 위험 또한 공유한다. 오히려 위험 발생률이 높기에 더욱 까다롭다.


# 비순차적 명령어 처리
**비순차적 명령어 처리**(Out-of-Order Execution, OoOE)는 명령어들을 순차적으로 실행하지 않는 기법이다. 다시 말해 순서를 바꿔 실행해도 무방한 명령어를 먼저 실행하여 명령어 파이프라인이 멈추는 것을 방지하는 기법이다.

예를 들어 명령어 A,B가 실행되고 있고 C는 A, B의 데이터를 기다려야 하고 그 뒤의 D와 E는 실행에 필요한 데이터가 준비되어 있다면 D와 E를 C와 순서를 바꿔서 실행하는 것이다.

이러한 기법을 수행하는 CPU는 명령어들이 순서를 바꿀 수 있는지를 판단할 수 있어야 한다.
